## Discussion Summary

- Thushara demonstrated the existing internal asset system: a basic Azure AD–authenticated web app without a dashboard, listing categories (laptops, displays, mobiles, etc.) and using admin-only “New Data” screens to manage models, memory, processor, and other master data.
  ​

- Current asset form includes auto-generated asset number, owner (TIQRI companies or customer), model, user (from HR now, Azure AD in future), processor, RAM, serial number (admin-only editable), status, screen size, vendor, warranty, purchase date, lease flag, comments, and a “problem reporter” flag, plus audit logs tracking who changed what.
  ​

- Product owner wants the new system to offer a richer dashboard showing approvals required, recent changes, pending actions, high-level counts by category and status, and separation between IT/hardware and admin/facilities assets, with both bulk and single asset import.
  ​

- The team’s elicitation questions covered asset tagging, stakeholder roles, attachments, form customization, asset types, volume tracking, and dashboard behavior; Thushara clarified that asset IDs must be auto-generated, serial numbers are unique for electronic assets, and non-serial items like tables should still use asset numbers.
  ​

- Key stakeholders are IT, IT admins, and finance; external users such as auditors will not get direct system access and will instead consume exported reports, but employees can log in via Azure AD SSO to view only their own assigned assets.
  ​

- The system should support file attachments (e.g., invoices), configurable/custom fields, admin-managed brands and models to avoid duplicates, and category-dependent forms where fields like RAM and processor appear only for relevant asset types.
  ​

- Financial data should capture purchase price including tax and shipping, support multiple currencies (NOK, USD, LKR), be encrypted, and ideally be updated by finance while IT handles asset entries, with cloud billing tracked by actual monthly cost using full-month charges for mid‑month changes.
  ​

- Bulk CSV import should import all valid rows, flag erroneous lines with clear messages, and not require an undo feature; errors should be fixable by users based on line information.
  ​

- Integration requirements include Azure AD SSO with MFA handled by Azure, optional Microsoft Teams integration for notifications, and no SMS support; the inventory system is separate from service desk ticketing and will not handle request workflows.
  ​

- For lifecycle and compliance, the system should support soft deletion, retain logs for about five years, track disposal reasons (sold, stolen, e‑waste, etc.), maintain audit trails, allow condition updates on return, and surface frequently failing assets on the dashboard.

## Decisions

- Asset IDs will be auto-generated with a meaningful pattern to be shared by Thushara; serial numbers remain unique for electronic assets, while non‑serial items rely on asset numbers.
  ​

- Categories, brands, and models are centrally managed via an admin console with department-specific admins to prevent duplicates and maintain data quality.
  ​

- The new system will implement an Azure AD–based SSO with MFA, employee self‑view (own assets only), no direct access for external users, and optional Teams integration for notifications (e.g., overdue returns).
  ​

- Attachments (e.g., invoices), financial fields (price, tax, shipping; multi-currency), and software license data (keys, expiry dates) will be stored and encrypted, with finance able to view and request corrections.
  ​

- Bulk import will support partial success (import valid rows, report failed ones), and no dedicated undo-import workflow will be implemented.
  ​

- The inventory system will not include ticketing or request flows; asset requests remain in the existing help desk tools, while inventory focuses on assignment, lifecycle, and reporting.
  ​

- Soft delete, five‑year log retention, disposal reason tracking, and dashboards highlighting assets with repeated failures are in scope for the future system.
